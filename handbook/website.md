# Websites

Each product has a static website (`<product>-website`) deployed as Cloudflare Workers static assets
from the committed `public/` directory. There is no framework and no Node dependency; pages are
generated by Python (standard library only) from `i18n/*.json` and `changelog.json`.

## Shared generator

The generator, checks and runtime scripts live in the `sitekit` repository and are vendored into each
website repository. A website repository owns only:

- `i18n/languages.json` and `i18n/<code>.json` (English is the source)
- `changelog.json` (written by the app's `website-changelog.py`, never by hand)
- `public/style.css`, `public/og.png`, product icons and screenshots
- the product-specific home sections

## Rules

- Nine languages (en, zh, zh-hant, ja, ko, fr, de, es, pt); every key exists in every language.
- Every page has exactly one address per language; no redirects, no aliases. Legal pages are
  `/terms`, `/privacy`, `/refund` and are the only place those texts live (the app links to them).
- One fact, one source: numbers in legal text (plan limits, device count, prices) are checked across
  all languages by `check_facts.py`.
- No analytics, no cookies, no third-party scripts; CSP is set in `public/_headers`.
- The download button reads `https://dl.<domain>/latest.json`; release history is rendered from
  `changelog.json`.

## Checks (local and CI, identical)

```
python3 scripts/sitekit/check_i18n.py   # structure, tags, links, placeholders match English
python3 scripts/build.py        # regenerate public/
git diff --exit-code public/    # committed output matches the sources
python3 scripts/sitekit/check_site.py   # missing pages, broken links and anchors, CSP violations
python3 scripts/check_facts.py  # legal facts consistent across languages
```

`scripts/sitekit/preview.py` serves `public/` locally with Cloudflare's trailing-slash and 404 behaviour.

## Deploy

Cloudflare's Git integration deploys `main` with `npx wrangler deploy` and an empty build command.
`workers_dev` and `preview_urls` are off; the custom domain is bound in the dashboard. After a repository
transfer the Git connection must be re-authorized in the dashboard.
